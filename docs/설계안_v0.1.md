## 1. Executive decision

### 1-1. 판정: GO

**GO.** 조건 없음. 아래 9절 MVP 범위 안에서 이번 학기에 완성한다.

근거는 아이디어가 아니라 이미 수행한 반증 실험이다.

- 실제 자료(공주시 읍·면 10곳, 법정리 161곳, 보건지소 10곳, 2026-04-13 의과 순회진료 일정)에서 **자원이 희소한 주 10~15 진료일 구간에 실제 trade-off가 존재**한다. B=15·15분 기준에서 서로 우열이 없는 배분이 약 6개다.
- 현재 공주시 실제 규모가 약 주 10 진료일이므로 **희소성을 인위적으로 만들지 않았다.**
- 가장 강한 교육 메시지가 데이터에서 확인됐다. **"평균이 비슷해도 어느 지역이 서비스를 잃는지는 배분 방식에 따라 크게 달라진다."**
- 계산은 161×10 접근시간 행렬 하나로 끝난다. 런타임 서버·외부 API·새 비용이 필요 없다.

### 1-2. 최종 제품 정의

> **Shrinking City Lab**은 실제 한국 인구감소지역 자료를 단순화해 공공서비스 배분의 **공간적 trade-off를 직접 체험**하는 교육용 시뮬레이션 시리즈다.
> 첫 시나리오 **「공주 보건지소, 진료일을 나누다」** 에서 플레이어는 공주시 읍·면 10곳의 보건지소에 **제한된 주당 진료일**을 배분하고, 배분할 때마다 3D 지형 위에서 **어느 마을에 진료가 닿고 어느 마을이 잃는지**를 즉시 본다. 세 개의 서로 다른 목표로 같은 자원을 배분해 보고, 마지막에 세 결과를 나란히 놓아 "평균 뒤에 숨은 지역별 희생"을 확인한다. 한 판은 5~10분이다.

이 제품이 **아닌 것**: 실제 공주시 행정 평가, 최적 정책 추천 도구, 의료정책 의사결정 시스템, 도시건설 게임.

### 1-3. 왜 이 형태로 좁혔는가

| 결정 | 이유 |
|---|---|
| 자원은 **금액이 아니라 진료일** | 실제 운영비 자료가 없다. 진료일은 공개 일정에서 그대로 읽히는 실제 단위다 |
| 미션 자원은 **실제 10일 + 가정 5일 = 15일** | 10일은 2026-04-13 일정의 실제 합, +5일은 명시적 게임 가정. 15는 전수실험에서 trade-off가 실제로 존재한 희소구간(10~15) 안에 있다(4-4절) |
| 시나리오 **하나**, 지역 **하나** | 검증된 데이터가 공주 보건지소 하나다. 잠긴 시나리오 목록 같은 가짜 범위를 만들지 않는다 |
| **폐쇄 게임이 아니라 배분 게임** | 실제 구조가 "지소는 있지만 진료일이 부족하다"이다. 10곳 모두 존재하고, 0일도 하나의 배분이다 |
| **총점 없음, 6개 지표 + 지도** | 하나의 점수는 trade-off를 숨긴다. 교육 목표가 바로 그 trade-off다 |
| **미션 3개 + 튜토리얼 + 실험실** | 서로 다른 목표 세 번이 "정답 하나"를 무너뜨리는 최소 구성이다. 콘텐츠를 더 늘리지 않는다 |
| **런타임 계산은 전부 브라우저** | 행렬 161×10 합산이라 즉시 계산된다. 서버·계정·실시간 데이터가 없어 배포·전시가 단순하다 |
| **3D는 지형 모형** | 공주는 산과 강이 접근성을 결정한다. 지형·도로·마을 분포가 보여야 "왜 저 마을에 안 닿는가"가 이해된다. 건물 모델링은 하지 않는다 |
| **데스크톱 전시 우선, 모바일 제외** | 3D + 패널 + 지도 읽기를 5분 안에 하려면 큰 화면이 필요하다. 범위를 늘려 완성도를 희생하지 않는다 |

## 2. Product thesis

### 2-1. 제품명

시리즈명은 **Shrinking City Lab**으로 확정을 권고한다. 한국어 부제는 "인구감소도시 공공서비스 배분 시뮬레이터"를 그대로 쓴다. 시나리오명은 아래에서 고른다.

| 후보 | 시나리오명 | 전시 헤드라인(30초 이해용) | 평가 |
|---|---|---|---|
| **A (권고)** | **진료일을 나누다 — 공주 보건지소 편** | 보건지소 10곳, 지금은 주 10일. 5일이 더 생긴다면 어디에 두시겠어요? | 행동(나누다)과 대상(진료일)이 이름에 있다. 처음 보는 사람이 무엇을 하는지 바로 안다 |
| B | 닿는 날 — 공주 보건지소 편 | 당신의 배분에 진료가 닿지 않는 마을은 어디입니까? | 시적이고 짧다. "닿는다"가 핵심 지표(15분 안 진료일)와 연결된다. 다만 첫 화면에서 설명이 한 줄 더 필요하다 |
| C | 열 개의 지소, 열다섯 날 | 같은 15일, 다른 배분, 다른 희생 | 리듬이 좋다. 숫자가 미션 총량(15)에 묶여 실험실(10~20일)과 어긋난다 |

문서 나머지는 A로 쓴다. 이름이 바뀌어도 화면 구조는 바뀌지 않는다.

### 2-2. 문제

인구가 줄고 전문인력이 부족한 지역에서 공공서비스는 **"있다/없다"가 아니라 "얼마나 자주 열리는가"** 의 문제가 된다. 공주시 읍·면 보건지소 10곳 중 의과 진료가 열리는 곳은 4곳이고, 그 4곳도 주 1일에서 5일까지 다르다. 이 배분이 어떤 마을에 어떤 결과를 만드는지는 평균 숫자 하나로는 보이지 않는다. 도시·지역계획을 배우지 않은 사람이 이 **공간적 trade-off를 몸으로 이해할 도구**가 없다.

### 2-3. 사용자

| 구분 | 누구 | 상황 |
|---|---|---|
| 1차 | 캡스톤 전시 관람객(비전공 학생·심사위원·일반인) | 부스 앞에서 처음 보고, 설명 없이 5~10분 플레이한다 |
| 2차 | 도시·지역계획, 행정, 보건 전공 학생과 교육자 | 수업·세미나에서 "형평 vs 효율"을 설명하는 실습 도구로 쓴다 |
| 확장 가설 | 지자체 실무자 | **이번 제품의 대상이 아니다.** 향후 가능성으로만 둔다 |

### 2-4. 1차 사용 맥락

- 전시 부스의 데스크톱(≥1280px, 마우스·키보드). 한 사람이 서서 또는 앉아서 한 판.
- 도움 없이 시작해야 한다. 30초 안에 "무엇을 하는 작품인지", 5~10분 안에 핵심 메시지.
- 세션은 저장되지 않는다. 다음 관람객을 위해 스스로 초기화된다.

### 2-5. 학습 목표 (플레이 후 이해해야 하는 것)

1. **같은 자원이라도 목표가 다르면 좋은 배분이 다르다.** 평균을 올리는 배분과 빈 곳을 없애는 배분은 다른 지도가 된다.
2. **평균 뒤에는 지역별 희생이 숨어 있다.** 평균이 비슷한 두 배분이 서로 다른 마을을 0일로 만든다.
3. **"닿는다"의 기준(10·15·20분)이 바뀌면 같은 배분의 평가가 바뀐다.** 기준 자체가 선택이다.

### 2-6. 차별점

| 비교 대상 | 그것이 하는 일 | 이 제품이 다른 점 |
|---|---|---|
| GIS 접근성 분석 도구(ArcGIS·QGIS 등) | 전문가가 지표를 계산한다 | 계산은 이미 되어 있다. 사용자는 **배분을 바꾸고 결과를 보는 데만** 집중한다. 전문 지식 0 |
| 도시건설 게임(SimCity 계열) | 성장·돈·건설. 가상 도시 | **실제 지역, 실제 인구, 실제 일정.** 짓지 않고 나눈다. 돈이 없다. 성장하지 않는다 |
| 정책 대시보드 | 현재 상태를 보여준다 | 사용자가 **가상의 배분을 직접 만들고** 실제 현재와 비교한다 |
| 최적화 솔버 | 최적해를 준다 | **최적해를 주지 않는다.** 서로 우열이 없는 배분들의 존재 자체를 보여준다 |

### 2-7. 하지 않는 것

- 실제 공주시 정책 평가·추천. 실제 의료 수요·질병·의료비 모델.
- 금액 예산, "예산 n% 절감" 류 표현.
- 하나의 종합점수·등급·별점.
- 최적해·추천 배분을 미리 알려주는 기능.
- 이동진료·원격협진의 효과 모델(검증되지 않았다).
- 계정·저장·멀티플레이·랭킹.
- 전국·다른 시군·다른 공공서비스 분야.

## 3. Core gameplay

### 3-1. 한 판의 흐름 (약 8분)

| 시각 | 단계 | 플레이어가 하는 일 | 화면 |
|---|---|---|---|
| 0:00 | 시작 | 헤드라인을 읽고 [시작]을 누른다 | S0 |
| 0:10 | 소개 3장 | 공주 읍·면과 인구 → 보건지소 10곳과 현재 진료일 → "진료일 = 나눌 자원" | S1 |
| 0:50 | 튜토리얼 | 현재 실제 배분(주 10일)을 지도에서 읽는다. 기준을 10→15→20분으로 바꿔 같은 배분의 평가가 변하는 것을 본다. 진료일 1일을 옮겨 본다 | S2 |
| 2:00 | 미션 1 「평균을 끌어올려라」 | 브리핑에서 "실제 10일 + 가정 5일 = 15일"을 보고, 15일을 배분해 평균 진료일을 목표 이상으로. 확정 → 디브리핑에서 0일이 된 마을을 본다 | S3→S4→S5 |
| 4:00 | 미션 2 「어디에도 빈 곳이 없게」 | 같은 15일로 가장 불리한 읍·면을 끌어올린다. 평균과 두꺼운 서비스가 떨어지는 것을 본다 | S3→S4→S5 |
| 6:00 | 미션 3 「두껍게 닿게」 | 같은 15일로 주 3일 이상 닿는 주민을 늘린다. 또 다른 지도, 또 다른 희생 | S3→S4→S5 |
| 7:30 | 마무리 「세 개의 공주」 | 세 배분을 나란히 본다. "평균은 비슷, 0일 마을은 다르다" | S6 |
| 8:00 | 종료 또는 실험실 | 실험실에서 총량·기준을 바꿔 자유롭게 배분하거나 처음으로 | S7 |

전시에서는 어느 단계에서든 떠날 수 있어야 한다. 미션을 건너뛰어도 S6은 참고 배분으로 채워진다(7-5절).

### 3-2. 핵심 반복 루프

```text
지소 하나의 진료일을 +1 또는 -1 한다
  → 그 지소의 탑 높이가 바뀐다 (0.2초)
  → 15분 안에 그 지소가 닿는 마을들의 상태가 바뀌고 한 번 깜빡인다
  → 6개 지표가 갱신되고 기준선 대비 ▲▼가 붙는다
  → 읍·면 목록에서 좋아진 곳·나빠진 곳이 바뀐다
  → 플레이어가 "누가 잃었는가"를 보고 다음 +1/-1을 정한다
```

한 번의 조작이 **한 지소·그 지소의 도달 마을·6개 지표·읍면 목록** 네 곳에 동시에 반영되는 것이 핵심 감각이다. 조작과 결과 사이에 확인 단추나 로딩이 없다.

### 3-3. 무엇이 재미·긴장·학습을 만드는가

| 원천 | 설명 |
|---|---|
| **유한한 풀** | 15일이 다 놓이면 어딘가에서 빼야 다른 곳에 놓을 수 있다. 모든 +1은 어딘가의 -1이다 |
| **즉시 보이는 희생** | 빼는 순간 그 지소만 닿던 마을이 **빈 고리(0일)** 로 바뀐다. 숫자보다 먼저 지도가 아프다 |
| **목표와 부작용의 충돌** | 미션 지표는 올라가는데 다른 지표가 떨어진다. 6개 타일이 동시에 움직이므로 숨길 수 없다 |
| **지형이 주는 직관의 배신** | 가까워 보이는 마을이 산 너머라 15분 밖이다. 도달선을 켜 보면 이유가 보인다 |
| **세 번의 다른 정답** | 미션이 끝날 때마다 "다른 목표였다면"이 다른 지도를 보여준다. 마지막에 셋이 나란히 놓인다 |
| **배분 지형도** | 가능한 모든 배분 속에서 내 점이 어디 있는지 본다. 위쪽 끝과 오른쪽 끝이 다른 배분임을 눈으로 확인한다 |

### 3-4. 성공·실패·완료의 의미

- **달성**: 미션 지표가 목표치 이상. 목표치는 그 미션 지표를 **가능한 모든 배분 중 상위 10%** 로 만드는 경계값이다(7-7절). 달성해도 점수·별은 없다. 대신 "가능한 배분 중 상위 n%"를 알려준다.
- **미달**: "목표까지 주 0.3일"처럼 남은 거리만 알려주고 계속 배분할 수 있다. **미달이어도 [이대로 확정]이 가능**하다. 디브리핑은 항상 열린다(전시에서 막히면 안 된다).
- **완료**: 디브리핑을 읽고 다음으로 넘어가는 것. 미션의 완료는 달성이 아니라 **"내 배분이 무엇을 잃었는지 봤다"** 이다.
- 게임 오버 없음. 시간 제한 없음.

### 3-5. "정답 하나 맞히기"가 되지 않게 하는 구조

1. 미션마다 목표 지표가 다르고, 세 목표를 동시에 만족하는 배분은 없다(데이터로 확인됨).
2. 결과 화면은 미션 지표 하나가 아니라 **6개 지표 전부와 지도**를 보인다.
3. 목표치는 "상위 10%"라는 **범위**이며 단일 값이 아니다. 같은 미션을 달성하는 배분이 여럿이다.
4. 디브리핑의 **배분 지형도**(4-8절)는 서로 우열이 없는 배분들을 함께 보인다.
5. 화면 어디에도 "최적", "추천", "정답", "가장 좋은 배분"이라는 말이 없다(5-11절 금지어).

### 4-2. 진료일(clinic-day)의 의미

- 정의: **한 보건지소에서 일반진료가 열리는 하루(주당).** 화면 표기는 "진료일", 값은 "주 n일".
- 지소당 0~5일 정수. 플레이어가 놓는 값은 항상 정수다.
- 현재 실제 배분(2.5·1.5 같은 격주 평균)은 **참고선으로만** 표시하고 계산에도 소수 그대로 쓴다. 플레이어가 격주를 만들 수는 없다.
- 진료일은 실제 의료서비스 전체를 나타내지 않는다. 진료 과목·의료진 수·장비·검사·응급은 모두 밖이다. 이 문장은 8절의 한계 문구 세트에 들어간다.

### 4-3. 접근시간과 10·15·20분의 의미

- 접근시간 t(리, 지소) = 리 대표점에서 지소까지 **도로망 자동차 최단 시간(분)**, OSRM car, 혼잡·신호 대기·주차·진료 대기 없음. 화면 용어는 항상 **"도로망 접근시간"**. "이동시간", "걸리는 시간"이라 쓰지 않는다.
- 기준 T ∈ {10, 15, 20}분. **"닿는다" = t ≤ T.**
- 15분은 기본값이지만 정답이 아니다. 튜토리얼이 같은 배분을 10·15·20분으로 바꿔 보이며 **"기준이 바뀌면 평가가 바뀐다"** 를 첫 학습으로 삼는다.
- 미션 목표는 15분 기준으로 판정한다. 플레이 중 기준을 바꾸면 모든 지표가 그 기준으로 다시 계산되고 미션 카드에 "미션 판정은 15분 기준" 표시가 뜬다.

### 4-4. 자원 총량 B — 10일은 실제, +5일은 가정, 15일은 가상 정책실험

| 구성 | 값 | 분류 | 어디에 |
|---|---|---|---|
| 현재 진료자원 | 주 10일 | **실제 자료** — 2026-04-13 의과 순회진료 일정의 합 | 튜토리얼, 실험실 기본값, 모든 비교의 기준선 `현재 실제` |
| 추가 진료자원 | +5일 | **게임 가정** — "일반진료 자원 5일이 추가 확보됐다면". 실제 계획·예산·인력 근거 없음 | 미션 1·2·3 |
| 플레이 자원 | 주 15일 | **가상 정책실험** — 위 둘의 합 | 미션 1·2·3 |
| 실험실 총량 | 주 10~20일 | 10일은 실제, 10을 넘는 부분은 전부 가정 | 실험실(기본 10) |

**왜 15인가 (내부 설계 근거).** 기존 전수실험에서 실제 trade-off가 존재하는 희소구간은 B=10~15였고, B=15·15분에서 서로 우열 없는 배분이 약 6개로 "세 미션이 서로 다른 지도를 만든다"가 보장된다. B≥20에서는 분산형 배분 하나가 거의 모든 지표를 이겨 선택 갈등이 크게 약해진다. 15는 그 희소구간의 위쪽 끝이면서 실제 10에서 가장 가까운 확장이다. 게임 밸런스를 위해 고른 임의의 수가 아니다.

**무엇이 아닌가.** "공주시가 실제로 5일을 늘려야 한다"는 권고가 아니다. 추가 5일이 실제로 확보될 수 있는지, 어떤 인력·예산이 필요한지는 이 모델이 말하지 않는다.

**UI·디브리핑에서 혼동을 막는 규칙.**

1. 15가 처음 나오는 곳(S3 미션 1 브리핑)에서 항상 `실제 10일 + 가정 5일`로 분해해 보이고 두 배지를 나란히 붙인다. 이후에도 `15일`을 분해 없이 단독으로 쓰지 않는다.
2. 진료일 풀은 15칸 중 10칸을 실선, 5칸을 점선 테두리로 그리고 캡션 `실제 10일 + 가정 5일`을 붙인다. 이것은 "총량 중 5일이 가정"이라는 표시일 뿐이다. **놓은 진료일 하나하나를 실제/가정으로 구분하지 않는다**(진료일은 서로 같다).
3. 미션 결과·디브리핑의 기준선 `현재 실제`는 10일이다. 그래서 내 배분(15일)과의 차이에는 **재배분 효과와 추가 5일의 효과가 섞여 있다.** 디브리핑은 이 사실을 고정 한 줄로 밝힌다(5-6절 블록 1).
4. 배분 지형도의 구름은 B=15 배분들이고 현재 실제 ◇는 B=10 점이다. 라벨을 `현재 실제 (10일)`로 쓴다(4-8절).
5. 실험실에서 총량 문구는 항상 `실제 10일 + 가정 {B−10}일`이다(B=10이면 `실제 10일`).
6. "5일을 늘려야", "추가 확보가 필요" 같은 권고형 문장은 금지어다(5-12절).

사용자가 미션 자원을 10일로 바꾸길 원하면 목표치(7-7절)와 참고 배분(7-6절)은 같은 규칙으로 자동 재산출되도록 설계한다.

### 4-5. 계산 정의

기호는 문서용이다. 화면에는 나오지 않는다.

- 리 i (161), 인구 P_i. 지소 j (10), 배분 x_j ∈ {0,…,5}. 총량 Σ x_j ≤ B.
- 접근시간 t_ij (분). 기준 T.
- **리의 접근 가능 진료일** A_i(T) = min(5, Σ_{j: t_ij ≤ T} x_j).
- **읍·면 m의 서비스 수준** S_m = Σ_{i∈m} P_i·A_i / Σ_{i∈m} P_i (인구가중 평균).
- **운영 지소** = x_j ≥ 1인 지소. 리 i의 **가장 가까운 운영 지소 시간** n_i = min_{j: x_j≥1} t_ij (운영 지소가 없으면 정의 안 됨).

### 4-6. KPI 정의

| # | 화면 이름 | 계산 | 화면 표현 | 갱신 | 어떤 판단을 돕나 |
|---|---|---|---|---|---|
| 1 | **평균 진료일** | Σ P_i·A_i / Σ P_i | `주 2.4일` + 작은 글씨 `15분 안 · 인구 가중 · 최대 5일` | 조작 즉시 | 효율. "전체적으로 얼마나 두껍게 닿나" |
| 2 | **주 1일 이상 닿는 주민** | Σ P_i [A_i ≥ 1] | `31,200명 (78%)` + 둘째 줄 `닿지 않는 주민 9,000명` | 조작 즉시 | 기본 보장. 0일 주민 수가 함께 보인다 |
| 3 | **주 3일 이상 닿는 주민** | Σ P_i [A_i ≥ 3] | `12,400명 (31%)` | 조작 즉시 | 두꺼운 서비스 |
| 4 | **가장 불리한 읍·면** | argmin_m S_m (동률이면 0일 주민이 많은 곳) | `탄천면 · 주 0일` | 조작 즉시 | 최악 지역 보호 |
| 5 | **읍·면 격차** | max_m S_m − min_m S_m | `주 4.2일 차이` + `가장 높은 곳 의당면 4.2 · 가장 낮은 곳 탄천면 0` | 조작 즉시 | 형평 |
| 6 | **90% 접근시간** | P_i 가중 n_i의 90퍼센타일 | `24분` + 문장 `주민 10명 중 9명은 이 시간 안에 운영 지소에 닿아요` + 미니 막대 `10분 안 a% · 15분 안 b% · 20분 안 c% · 그 밖 d%` | 조작 즉시 | 먼 곳까지의 거리. 10·15·20분 서비스권을 한눈에 |
| 7 | **지역별 변화** | ΔS_m, ΔA_i (기준선 대비) | 타일이 아니라 읍·면 목록 ▲▼ + 지도 증감 모드로 표현 | 조작 즉시 | 누가 이득·손실인가 |

표기 규칙: 진료일은 소수 1자리(`주 2.4일`), 인구는 천 단위 구분 + 백분율 정수, 시간은 분 정수. 값이 정의되지 않으면(운영 지소 0곳) 숫자 대신 `운영 지소 없음`을 다른 글꼴·크기로 쓴다. 색만으로 상태를 표현하지 않는다.

각 타일의 ⓘ는 한 문단 설명과 배지(실제 자료·계산값·게임 가정)를 연다. 예: 평균 진료일 → "각 마을에서 도로망 15분 안에 있는 지소들의 진료일을 더한 값(최대 5일)을, 마을 인구로 가중 평균했어요. 진료일과 5일 상한은 게임 가정이에요."

### 4-7. 지역별 변화(누가 이득·손실인가)

- **기준선**은 하나이며 사용자가 고른다: `현재 실제(2026-04)` / `직전 확정 배분` / `저장한 배분 A·B·C`. 미션 중 기본값은 `현재 실제`.
- 리 단위: ΔA_i를 세 상태로 본다. `좋아짐(+1일 이상)` / `같음` / `나빠짐(−1일 이상)`. 크기는 |ΔA_i|.
- 읍·면 단위: ΔS_m을 소수 1자리로, `▲0.8` `▼1.2` 형태.
- **이번 조작으로 상태가 바뀐 마을**은 기준선과 별개로 0.6초 한 번 깜빡인다(6-9절). 즉 "직전 한 걸음"은 깜빡임으로, "기준선 대비"는 증감 모드로 구분한다.

### 4-8. 배분 지형도 (전수 계산)

- B와 T가 정해지면 가능한 배분은 유한하다(B=15: 831,204개, B=10: 85,228개 — 총량을 모두 놓은 배분 기준). 각 배분의 KPI 1~6을 **오프라인에서 전부 계산**해 두 축 요약(밀도 격자)과 **서로 우열이 없는 배분 목록**(어느 지표도 다른 배분에 모두 뒤지지 않는 것)을 정적 파일로 둔다.
- 디브리핑에서 x축 `평균 진료일`, y축 `가장 불리한 읍·면`의 산점 밀도(미션에서는 B=15 배분들) 위에 내 배분 ★, `현재 실제 (10일)` ◇, 다른 미션 결과 ●, 우열 없는 배분 ○를 놓는다. ◇만 총량이 다르다는 것을 라벨이 말한다.
- 읽는 문장(고정): "오른쪽 위로 갈수록 두 지표가 모두 좋아요. 그런데 오른쪽 끝과 위쪽 끝은 서로 다른 배분이에요."
- 이것은 최적해 제시가 아니다. **우열 없는 배분이 여럿**이라는 사실을 보이는 장치다.

### 4-9. 모델의 한계 (제품 안에 나와야 하는 문장)

1. 교육용 단순화 모델이에요. 실제 정책 권고가 아니에요.
2. 시간은 도로망 자동차 접근시간이에요. 실제 개인의 이동시간·교통혼잡·대기시간은 반영하지 않아요.
3. 진료일은 게임용 단위예요. 진료 과목·의료진·장비 같은 실제 의료서비스 전체를 나타내지 않아요.
4. 마을 주민 전체가 마을 대표점 한 곳에 있다고 봤어요.
5. 공주 시내(동 지역)의 보건소·병원, 민간 의원, 다른 시군의 시설은 모델에 없어요.
6. 법정리별 65세 이상 인구는 읍·면 비율로 나눈 추정값이라 화면에 쓰지 않았어요.
7. 실제 운영에는 이 모델이 표현하지 않는 인력·전문과·행정 제약이 있어요.
8. 진료일을 어디에 두어도 실제로 그렇게 운영할 수 있는지는 이 모델이 말하지 않아요.
9. 미션의 진료일 15일 중 5일은 "추가로 확보됐다면"이라는 가정이에요. 실제로 5일을 늘려야 한다는 뜻이 아니에요.

### 5-6. S5 미션 결과·디브리핑

무대는 확정 배분을 **증감 모드(기준선 현재 실제)** 로 보이고, 카메라는 전체 시점으로 돌아간다. 패널이 결과 패널로 바뀐다(스크롤).

| 순서 | 블록 | 내용·문구 |
|---|---|---|
| 1 | 판정 | `미션 1 · 평균을 끌어올려라` / `달성 · 가능한 배분 중 상위 4%` 또는 `미달 · 상위 23%` (판정 문구는 크기만 다르고 색으로 구분하지 않음). 그 아래 고정 한 줄: `이 결과는 실제 10일에 가정 5일을 더한 15일 기준이에요. 현재 실제(10일)와의 차이에는 5일이 늘어난 효과도 섞여 있어요.` |
| 2 | 얻은 것 | 기준선 대비 가장 많이 오른 지표 2개: `평균 진료일 주 1.9일 → 2.6일 (▲0.7)` |
| 3 | **잃은 것** | `진료가 닿지 않게 된 마을 {n}곳 · {인구}명` + 읍·면별 묶음 목록(이름·인구, 최대 5줄 + 더보기). 이 블록은 얻은 것과 같은 크기이며 항상 있다. 잃은 마을이 0이면 `기준선보다 나빠진 마을은 없어요` |
| 4 | 6개 지표 표 | 열: `현재 실제 (10일)` · `내 배분 (15일)` · 차이(▲▼). 행: KPI 1~6 |
| 5 | 배분 지형도 | 4-8절 그래프 + 고정 문장 |
| 6 | 다른 목표였다면 | 다음 미션의 참고 배분(7-6절) 탑을 무대에 **회색 유령 탑**으로 겹쳐 보이고, 한 줄: `같은 15일로 "가장 불리한 읍·면"을 높인 배분은 이렇게 달라요. 다음 미션에서 직접 해 보세요.` [유령 배분 보기/숨기기] |
| 7 | 한계 한 줄 | 4-9절 문장 중 하나(미션마다 다른 것: M1=2번, M2=5번, M3=3번) |
| 8 | 버튼 | [다음 미션] · [다시 배분] · [이 배분 저장](실험실 슬롯으로) |

전환: [다음 미션] → S3. 마지막 미션이면 [세 개의 공주 보기] → S6.

### 5-7. S6 마무리 「세 개의 공주」

| 항목 | 내용 |
|---|---|
| 목적 | 세 배분을 나란히 놓아 "평균은 비슷, 잃는 지역은 다르다"를 확인 |
| 무대 | 카메라 **위에서 보기(정사영)**. 무대가 3열로 나뉘어 같은 지형 위에 M1·M2·M3 배분의 마을 상태와 탑을 보인다(작은 배수). 열 제목: `평균을 끌어올려라` `어디에도 빈 곳이 없게` `두껍게 닿게`. 미션을 건너뛴 열은 참고 배분으로 채우고 `참고 배분` 칩을 붙인다 |
| 패널 | 표 위 한 줄 `세 배분 모두 실제 10일 + 가정 5일 = 15일 기준 · 가상 정책실험`. 6개 지표 × 3열 표. 아래 고정 문장(값은 데이터): `평균 진료일은 {a} · {b} · {c}일로 비슷하지만, 진료가 닿지 않는 마을은 {n1} · {n2} · {n3}곳이고 서로 다른 곳이에요.` 그 아래 `0일이 된 마을`을 열별로 읍·면 이름 묶음으로 나열 |
| 상호작용 | 열 hover → 그 열만 색, 다른 열 흐려짐. 열 클릭 → 그 배분을 전체 무대로 확대(증감 모드), [세 개로 돌아가기] |
| 문구 | 마지막 한 줄: `같은 자원이라도 목표에 따라 좋은 배분이 달라요. 평균 뒤에는 늘 어느 지역의 희생이 있어요.` |
| 버튼 | [실험실로] · [처음으로] · [자료와 한계] |

### 5-8. S7 실험실

S4와 같은 화면에 미션 카드 대신 **실험 카드**가 있다.

| 요소 | 내용 |
|---|---|
| 총량 | `배분할 진료일 주 {B}일 = 실제 10일 + 가정 {B−10}일` 스텝퍼 10~20(B=10이면 `실제 10일`만). 바꾸면 현재 배분은 유지되고 풀만 바뀐다(초과 시 초과분만큼 + 비활성, 안내 `총량보다 {n}일 많아요. 빼 주세요`) |
| 기준 | 상단 스위치 그대로 |
| 슬롯 | `저장 A` `저장 B` `저장 C` + `현재 실제`. [현재 배분 저장] → 빈 슬롯. 슬롯 클릭 → 불러오기. 두 슬롯 선택 → **비교 모드**(6-10절): 무대 `A 보기 / B 보기 / 차이 보기` 토글, 패널 지표 표 2열 + 차이 |
| 힌트(Should) | B ≥ 20에서 첫 확정 시 한 줄: `총량이 넉넉해지면 한 배분이 거의 모든 지표에서 앞서요. 갈등은 자원이 희소할 때 생겨요.`(실험에서 확인된 사실) |
| 공유(Should) | [링크 복사] → 배분 10자리·B·T가 URL 쿼리에 실린 주소. 개인정보 없음 |

### 5-9. S8 자료와 한계

오버레이 한 페이지(어디서든 열고 닫으면 상태 유지). 순서: ① 이 작품은 무엇이고 무엇이 아닌가(2-7절 요약) ② 자료 출처·기준일 표(4-1절의 실제 자료 행) ③ 계산 방식(4-5·4-6절을 쉬운 말로) ④ 게임 가정 목록 ⑤ 한계 9문장(4-9절) ⑥ 만든 사람·학과·연도. 표의 모든 값은 데이터 manifest에서 읽는다(날짜를 문구에 하드코딩하지 않는다).

### 5-10. 모바일 범위 — 결정

- **<768px는 MVP에서 플레이를 지원하지 않는다.** 한 화면(헤드라인, 정적 조감 이미지 1장, `이 작품은 데스크톱 화면에서 플레이할 수 있어요`, `자료와 한계` 링크)만 제공한다.
- 768~1023은 하단 시트 구성으로 **플레이 가능**하되 QA 우선순위는 낮다.
- 이유: 3D 무대·10행 지소 목록·6타일·10행 영향 목록을 동시에 읽는 것이 핵심 경험이다. 좁은 화면에서 쪼개면 "조작 하나 → 네 곳 동시 반영"이 사라진다.

### 5-11. 접근성

- **색만으로 구분하지 않는다.** 마을 상태는 채움 정도(빈 고리/반/가득)와 외곽선으로, 증감은 ▲▼ 글리프와 방향으로, 판정은 문구로 구분한다.
- 무대의 모든 정보는 패널 표(지소 목록·KPI·읍면 목록·지역 카드)에도 있다. **패널만으로 플레이가 가능**하다. 3D는 이해를 돕지만 필수 경로가 아니다.
- 키보드: Tab 순서 상단바 → 패널 ① → ② → ③(행마다 −/+) → ④ → ⑤ → ⑥. 지소 행에서 `+`/`−`/`←`/`→`. 포커스 링 2px 항상 표시.
- 스크린리더: 조작마다 라이브 영역 한 문장 `{지소} 주 {n}일. 평균 진료일 {값}. 닿지 않는 주민 {값}명.` 그 이상은 읽지 않는다.
- 터치 타깃 ≥44px. 패널 본문 대비 4.5:1 이상. 무대 위 라벨은 흰 후광(halo) 처리.
- `prefers-reduced-motion`: 회전·카메라 이동·탑 애니메이션·깜빡임 모두 즉시 전환.
- WebGL 불가 시: 위에서 보기 2D 정적 렌더(6-13절)로 대체하거나, 최소한 `이 브라우저에서는 3D를 표시할 수 없어요` + 패널만으로 플레이.

### 5-12. 문구 원칙과 금지어

원칙: "~해요" 체. 한 문장 한 정보. 느낌표·이모지 없음. 내부 용어(OSRM·p90·Pareto·인구가중·매트릭스)는 화면에 나오지 않는다(ⓘ 설명에서만 쉬운 말로 풀어 쓴다). 시간은 항상 "도로망 접근시간" 또는 "도로망 {n}분".

| 금지 | 대신 |
|---|---|
| 최적, 최선, 추천, 정답, 가장 좋은 배분 | 목표 달성, 상위 n%, 우열 없는 배분 |
| 이동시간, 걸리는 시간 | 도로망 접근시간 |
| 예산, 절감, 비용 | 진료일, 총량 |
| 폐쇄, 폐지 | 미운영, 주 0일 |
| 고령층이 더 피해 | (쓰지 않음. 65세 이상은 읍·면 맥락 정보로만) |
| 공주시가 ~해야 한다 | (쓰지 않음) |
| 5일을 늘려야, 추가 확보가 필요, 진료일을 확대해야 | 5일이 더 확보됐다고 가정 (가상 정책실험) |
| 실제 주민이 ~분 걸린다 | 도로망 접근시간 기준 ~분 |

## 6. 3D / visual direction

### 6-1. 시각 콘셉트 — 「종이 지형 모형」

도시계획 스튜디오 책상 위의 **종이 지형 모형**. 무광 종이빛 지형, 연한 물, 가는 도로. 그 위에 데이터만 채도가 있다. 3D의 역할은 네 가지다.

1. **높낮이**: 왜 가까워 보이는 마을이 15분 밖인지(산줄기·강).
2. **분포**: 마을이 골짜기와 도로를 따라 흩어져 있고 중심지와 외곽이 갈라진다는 것.
3. **자원의 물리적 양**: 지소 탑의 높이 = 진료일. 배분이 "쌓아 올린 것"으로 보인다.
4. **도달**: 어느 마을이 켜지고 꺼지는가. 원이 아니라 마을의 상태로.

사실적 건물·나무·차량·날씨·야경은 만들지 않는다. 항공사진 텍스처도 쓰지 않는다(시각 소음·라이선스).

### 6-2. 카메라

| 항목 | 규칙 |
|---|---|
| 기본 시점 | 북쪽 위. 비스듬히 내려보는 원근 카메라. 지면 대비 앙각 50°. 공주 읍·면 전체가 패널을 뺀 영역 안에 들어오는 거리 |
| 회전 | 드래그로 방위 360° 회전 허용. 앙각 30°~90° |
| 확대 | 전체(1×)에서 읍·면 하나(약 6×)까지. 그 이상 확대 없음 |
| 이동 | 무대 경계(공주시 경계 + 여유) 밖으로 나가지 않음 |
| 프리셋 버튼(우하단) | `전체` `북쪽으로` `위에서 보기`(정사영 2D, 앙각 90°). 위에서 보기가 곧 2D 지도다 |
| 초점 이동 | 읍·면 클릭·더블클릭 시 0.6초 이동. 그 외 어떤 조작도 카메라를 움직이지 않는다(배분을 바꿔도 카메라는 그대로) |
| 대기 화면 | S0에서만 120초/1회전 자동 회전 |

### 6-3. 지형·물·도로·시가지

| 요소 | 표현 | 분류 |
|---|---|---|
| 지형 | 공개 DEM 기반 저해상 메시(전체 삼각형 예산 ≤20만). 수직 과장 1.5×. 고도별 색은 종이빛 2~3단(낮은 곳 밝음 → 높은 곳 약간 어두움). 짙은 그림자·안개 없음 | 실제 자료 |
| 금강·주요 하천 | 연한 청회색 면·선 | 실제 자료(OSM) |
| 도로 | 국도·지방도만 가는 밝은 선. 군도 이하 생략. 지형에 얹힘 | 실제 자료(OSM) |
| 읍·면 경계 | 가는 실선. 이름 라벨 항상(후광 처리). 가장 불리한 읍·면은 **굵은 점선 + `가장 불리` 라벨** | 실제 자료 |
| 시내(동 지역) | 회색 빗금 면 + 라벨 `공주 시내 · 범위 밖` | 실제 자료(경계) |
| 무대 밖 | 지형은 공주시 경계에서 부드럽게 잘라 종이 가장자리처럼 끝낸다 | |

### 6-4. 마을(법정리 161)

| 속성 | 표현 |
|---|---|
| 위치 | 대표점. 지형 위에 살짝 떠 있는 원판 |
| 크기 | 인구 3단계(삼분위, 범례에 실제 구간 표시). 반지름 비율 1 : 1.5 : 2.2 |
| 상태(접근 진료일 A_i) | **0일 = 빈 고리(짙은 외곽선, 채움 없음)** / **1~2일 = 반 채움(연한 색 + 외곽선)** / **3~5일 = 가득 채움(짙은 색)**. 채움 정도가 값을 말하므로 색맹에서도 읽힌다 |
| 라벨 | 확대 3× 이상 또는 hover·포커스 시 이름. 겹치면 인구 큰 것 우선 |
| hover | 원판 커짐 + 툴팁(이름·읍면·인구·15분 안 지소와 시간·접근 진료일) + **도달선**(6-6절) |

### 6-5. 보건지소(10)

| 속성 | 표현 |
|---|---|
| 형태 | 정사각 밑판 위에 **칸 5개**가 세로로 쌓인 탑. 채워진 칸 = 배분한 진료일, 빈 칸 = 가는 테두리(최대치가 항상 보인다) |
| 색 | 지소는 하나의 잉크색. 배분은 **높이**로만 읽힌다(색으로 구분하지 않음) |
| 0일 | 밑판 + 빈 틀 5칸 + 라벨 `미운영` |
| 현재 실제 참고 | 기준선이 `현재 실제`일 때 탑 옆에 **회색 얇은 유령 탑**(격주 평균은 반 칸) 표시. 토글 가능 |
| 라벨 | 이름 항상. 값 `주 3일`은 hover·선택 시 |
| hover | 탑 강조 + 패널 행 강조 + **도달선** |
| 선택(클릭) | 탑 밑판 링 + 탑 옆에 미니 스텝퍼 `− 3 +`(패널 행과 같은 상태). Esc·빈 곳 클릭으로 해제 |

### 6-6. 서비스 도달 — 원을 그리지 않는다

- **금지**: 지소 주변에 원·버퍼·등시선 면을 그리는 것. 도로망 시간은 원형이 아니며, 우리는 161점의 시간만 정확히 안다. 원은 틀린 그림이다.
- **도달의 진실은 마을의 상태**(6-4)다. 서비스권은 마을들이 켜진 모양으로 드러난다.
- **관계 읽기(UX 목적, 고정)**: 사용자가 지소·마을을 hover·선택·포커스했을 때, 그리고 조작으로 상태가 바뀐 마을에 대해 **"어느 지소가 어느 마을에 T 안에 닿는가"** 를 즉시 읽을 수 있어야 한다. 시간값(`도로망 12분`)이 함께 보여야 한다.
- **도달선(권고 표현)**: 위 목적을 채우는 한 방법이다. hover·선택된 지소에서 T 안의 마을들로(또는 마을에서 지소들로) 가는 가는 직선을 지형 위에 그리고 먼 쪽 몇 개에 시간 라벨을 붙인다. **161개 도달선을 항상 동시에 그리는 것은 요구가 아니다.** 강조·하이라이트·선 수 제한·라벨 간소화 같은 구체적 시각화와 성능 최적화는 구현자가 정한다. 원·버퍼로 대체하는 것만 금지다.
- 읍·면 면 채움: S_m에 따라 아주 연한 3단 톤. 읍·면 단위의 대략적 서비스 수준만 보인다. 범례에 `읍·면 평균 진료일` 3단 표시.

### 6-7. 증가·감소(증감 모드)

- 기준선 대비 ΔA_i로 마을 원판 위에 **▲ / ▼ 작은 입체 글리프**를 세운다. 크기는 |Δ| 1일 / 2일 / 3일 이상 3단. 변화 없음은 글리프 없음.
- 색: 좋아짐 파랑 계열, 나빠짐 갈색-주황 계열(적록 사용 금지). 글리프 방향이 색 없이도 뜻을 말한다.
- 상태 채움(6-4)은 증감 모드에서도 유지된다. 즉 "지금 0일인데(빈 고리) 기준선보다 나빠졌다(▼)"가 한 점에서 읽힌다.
- 패널 읍·면 목록의 ▲▼와 같은 글리프·같은 색.

### 6-10. 정책 A/B 비교 시각화

- 무대는 하나. 토글 `A 보기 / B 보기 / 차이 보기`.
- A·B 보기: 그 배분의 탑과 마을 상태. 전환은 크로스페이드.
- **차이 보기**: 탑은 A·B 두 높이를 나란히(A 잉크, B 회색 유령), 마을은 B−A의 ▲▼ 글리프(6-7절 규칙). 라벨 `A 대비 B`.
- 패널: 6개 지표 2열 + 차이 열. 두 배분의 `0일 마을` 목록을 나란히.
- S6 「세 개의 공주」는 이 규칙의 3열판(위에서 보기 고정).

**뜻이 먼저다.** 빛은 실제 의료진·차량의 이동이 아니라 **도로망 접근성 변화의 시각적 은유**다. 집은 실제 건물 위치·수가 아니라 **인구 규모를 전하는 디오라마 기호**다. 논·밭·숲·나무·지붕 색은 **풍경 표현이며 자료가 아니다**. 이 세 문장은 S8 `화면 표현`과 `읽는 법`에 그대로 나온다.

**데이터 채널은 셋뿐이다.** 빛(창·빛 번짐·길의 빛 = 진료가 닿는다), 등칸 수(진료일), ▲▼ 깃발(기준선 대비 증감). 풍경은 이 셋보다 밝거나 채도가 높을 수 없다. 호박빛은 데이터의 빛에만, 청록은 선택·포커스·목표 표시에만 쓴다(데이터 색 아님).

**S6 「세 개의 공주」**: 위에서 본 지도 세 장이 3D 무대와 **같은 집 자리**(같은 세계 생성)와 같은 땅 그림을 쓴다. 마을 = 집 점 + 빛(없음 / 작은 빛 / 큰 빛 + 번짐), 지소 = 둥근 명판의 점 다섯. 가장 불리한 읍·면 흰 점선, 시내 흐린 종이. 표와 문장은 보고서 종이(6-13·5-7 의미 그대로).

**카메라·줌별 정보.** 규칙은 6-2 그대로(북쪽 위, 기본 앙각 47°, 배분을 바꿔도 카메라는 가만, 읍·면 클릭·더블클릭만 이동). 전체(1×): 땅에 새긴 읍·면 이름, 지소 명판, 마을은 빛 덩어리. 2.2× 이상: 마을 이름, 명판에 `주 n일`, 읍·면 이름은 옅어진다. 6×: 창·문등·논 구획·나무 덩이.

**소리.** 저녁 디오라마의 소리 — 부드럽고 따뜻한 짧은 **합성음**(2026-09-24 다듬음, 사용자 지시: 유리 종·둔탁음·도장처럼 거칠고 기계적인 소리 대신 "부드럽고 감미롭고 따뜻한 저녁 디오라마의 소리"). 칼림바·오르골·펠트 망치 종·나무 말렛·아주 얇은 패드의 **질감을 빌리되** 특정 악기를 흉내 내지 않는다. 모두 Web Audio로 브라우저에서 만든다(사인 부분음을 더하는 모달 합성 — 외부 음원 파일 없음, 라이선스 문제 없음, 내려받을 것 없음). 음높이는 D장조 5음 음계(레·미·파#·라·시)라 어떤 순서로 겹쳐도 부딪히지 않는다. 모든 소리가 수식으로 만든 **방 울림 하나**(RT60 1.8초, 꼬리가 어두워진다)를 나눠 쓴다. 소리는 정보를 더하지 않는다(소리 없이도 모든 것이 화면에 있다). 기능 신호보다 분위기와 조작의 기분 좋은 감각을 우선한다.

**되풀이해도 피로하지 않게.** ① 마을 음 절제: 도착을 100 ms로 묶고 첫 닿음 + 주민 무게가 큰 묶음을 130 ms 이상 떨어뜨려 고른다. 음의 시각은 빛의 계획의 도착 시각 그대로다(소리가 빛을 따라간다). ② 습관화: 같은 갈래의 소리가 잇달면 조금씩 작아지고(바닥 0.5, 막힘·불씨 숨은 0.35) 쉬면 1.4초 시간 상수로 돌아온다. ③ 새 조작이 오면 앞 조작의 **아직 울리지 않은** 빛 번짐 음(마을 음·패드)을 거둔다. 불씨·점등·소등은 화면의 등칸과 짝이라 거두지 않는다. ④ 음마다 세기 ±6 %·음높이 ±4센트·시각 ±3 ms가 흔들린다(같은 조작을 되풀이해도 기계처럼 똑같지 않게). ⑤ 전체 음량은 낮게 둔다. 브라우저 QA가 오프라인 렌더로 한 조작·목표 달성의 최고 레벨이 −14 dBFS 아래인지, 0.15초 간격으로 여섯 번 눌러도 한 번보다 3 dB 넘게 커지지 않는지, 거두기가 되는지 잰다. ⑥ 어택은 2~35 ms로 둥글게 열어 딸깍이 없다. 네모·톱니파와 넓은 대역 잡음 폭발은 쓰지 않는다.

원칙: 첫 사용자 입력에서만 오디오를 연다(자동재생 규칙). 위 막대 [소리] 버튼(aria-pressed)으로 끄고, 선택은 이 브라우저에만 남는다. 움직임 줄이기에서는 불씨·번짐 소리 없이 점등 음과 맑은 음 하나만 낸다. 전시 90초 복귀는 소리 설정을 바꾸지 않는다. 약한 전시 PC에서도 끊기지 않게: 한 층 = 발진기 하나(배음은 PeriodicWave 한 장), 사인만 쓰는 목소리에는 거르개가 없고, 모든 자동화에 끝이 있으며(−54 dB에서 멈춘다), 방 울림은 하나를 나눠 쓴다(개발 PC 측정: 0.5초마다 누르는 극단적인 연타에서 한 코어의 약 3.7 %, 보통 속도 약 2 %). 사람이 듣고 판단할 청취 파일은 `app/scripts/sound-audition.mjs`가 실제 빛의 계획으로 만든다(장면 17개, `qa-shots/sound/`).

**성능.** 통합 GPU 1080p 60fps 목표(6-12 ⑤) 유지. 한 장면 약 35~40 드로우·50만 삼각형(집 808채 4묶음, 나무 약 8,700그루 2묶음, 빛 번짐 1묶음, 지소 탑·유령 탑 인스턴스, 길의 빛 지소당 1드로우). 멈춰 있으면 그리지 않는다(자동 회전·빛·카메라 움직임 때만). **적응 화질**: 이어서 그린 프레임 간격의 가운데값이 26 ms를 넘으면 픽셀 비율을 한 칸씩 낮추고(2 → 1.5 → 1 → 0.75), 가장 낮은 칸에서도 느리면 나무만 절반으로 줄인다(데이터 표현은 줄이지 않는다).

**이 절이 바꾸는 조항.** 5-0 레이아웃(패널 → 가장자리 HUD + 도크 + 점검 카드), 5-0 범례(기본 펼침 → `읽는 법` 기본 접힘), 5-5 ③(세로 10행 → 서→동 도크), 6-3·6-11·6-15(표현·팔레트), 6-4(집 한 채 + 크기 3단 → 집 묶음 + 빛 3단), 6-5(층 탑 → 진료등 탑), 6-6 마지막 줄(읍·면 면 채움 3단 톤은 없앤다 — 네 번째 데이터 채널이 되므로. 읍·면 값은 서랍·미션 2 막대·새긴 이름 아래 줄에 있다), 6-9·10-3 S4(무대와 지표의 **표시**는 빛의 도착을 따라 최대 약 1.2초 — 계산·판정·확정 가능 여부·라이브 문장은 즉시), 6-12 ①(풍경 요소는 데이터 채널을 쓰지 않는 조건에서 허용), 6-13(S6 지도 기호).

### 7-5. 마무리 「세 개의 공주」

5-7절. 미션을 건너뛴 열은 7-6절 참고 배분으로 채우고 `참고 배분` 칩을 단다. 종료 문장 고정.

### 7-6. 참고 배분

각 미션 지표에서 **가능한 모든 배분(B=15, T=15) 중 값이 가장 높은 배분 하나**(동률이면 0일 주민이 적은 것, 그래도 동률이면 첫 번째). 이름은 `참고 배분 · 평균형` `참고 배분 · 보장형` `참고 배분 · 두꺼운 서비스형`. 화면 문구는 "이 지표만 보면 가장 높은 배분 하나"이며 **"최적"이라 부르지 않는다.** 플레이어가 미션을 하기 전에는 절대 보이지 않는다(디브리핑 블록 6과 S6에서만).

### 7-7. 목표치 규칙

- 목표치 = 그 미션 지표를 **가능한 모든 배분(B=15, T=15) 중 상위 10%** 로 만드는 경계값. 진료일은 0.1 단위, 인구는 100명 단위로 사용자에게 유리하게 내림.
- `상위 n%` 표기 = 내 배분보다 그 지표가 높은 배분의 비율.
- 값은 데이터 전처리에서 자동 산출해 미션 데이터에 출처와 함께 기록한다. 손으로 정하지 않는다. 총량이 10으로 바뀌어도 같은 규칙으로 다시 나온다.

### 7-8. 실험실

| 항목 | 내용 |
|---|---|
| 목표 | 없음 |
| 시작 조건 | 현재 실제 배분(주 10일), B=10, 기준 15 |
| 자유도 | B 10~20, T 10·15·20, 슬롯 3개 저장·비교 |
| 배우는 것 | 총량이 커지면 한 배분이 거의 모든 지표에서 앞서 갈등이 사라진다(힌트 한 줄, Should) |
| 종료 | 없음. [처음으로] |

## 8. Trust & educational framing

### 8-1. 다섯 층

긴 면책문 한 장을 만들지 않는다. 대신 다섯 층으로 나눠 **그 정보가 필요한 순간에** 나온다.

| 층 | 어디 | 무엇 |
|---|---|---|
| 1 | S0 카드 하단 한 줄 | `이 작품은 실제 공주시 행정을 평가하거나 정책을 추천하지 않아요.` |
| 2 | S1 각 장 작은 글씨, S3 자원 배지·가정 설명 | 값마다 배지 + 기준일. 15일 총량은 항상 `실제 10일 + 가정 5일`로 분해되고 두 배지가 붙는다 |
| 3 | KPI ⓘ, 범례, 기준 스위치 도움말 | 계산 방식과 배지. `도로망 접근시간 · 혼잡·대기 없음` |
| 4 | 디브리핑 블록 7 | 미션마다 다른 한계 문장 1개 |
| 5 | S8 자료와 한계 | 출처·기준일 표, 계산, 가정, 한계 9문장 전부 |

상단바의 `자료와 한계`는 모든 화면에 있다. 무대 우하단 작은 칩 `자료 기준 2026-08-31 · 일정 2026-04-13 · 도로망 2026-09-10`은 항상 보이고 클릭하면 S8이 열린다(값은 manifest에서).

### 8-2. 데이터 배지

세 배지는 모양이 다르다(색만 다르지 않다).

| 배지 | 모양 | 문구 |
|---|---|---|
| 실제 자료 | 꽉 찬 사각 | `실제 자료 · {출처} · {기준일}` |
| 계산값 | 테두리 사각 | `계산값 · {방법 한 마디}` |
| 게임 가정 | 둥근 점선 사각 | `게임 가정` |

### 8-3. 출처와 기준일 표시 규칙

- 날짜와 출처 문자열은 **데이터 manifest 한 곳**에서 온다. 화면 문구에 하드코딩하지 않는다.
- 세 기준일(인구 2026-08-31, 진료일정 2026-04-13, 도로망 2026-09-10)은 항상 함께 표시한다. 하나만 보이면 오해가 생긴다.
- OSRM·OSM·DEM 버전은 S8에만 적는다.

### 8-4. 오해 방지 UX

| 오해 | 방지 |
|---|---|
| "공주시가 이렇게 해야 한다는 뜻" | 미션 이름이 정책이 아닌 **목표**다. 참고 배분을 "최적"이라 부르지 않는다. S6 종료 문장이 "정답"이 아닌 "희생"을 말한다 |
| "15일이 지금의 실제 상황" / "5일을 늘리라는 권고" | 15가 나오는 곳마다 `실제 10일 + 가정 5일` 분해와 두 배지, S3 가정 설명 문장, S5 판정 아래 고정 한 줄, 기준선 라벨 `현재 실제 (10일)`, 한계 9번 문장(4-4절) |
| "15분이 표준" | 튜토리얼 2단계가 기준 변경을 **필수 행동**으로 만든다 |
| "실제 주민이 12분 걸린다" | 도달선 라벨·툴팁 모두 `도로망 12분`. "이동시간" 단어 금지 |
| "진료일이 곧 의료서비스" | 진료일 정의를 S1 3장·ⓘ·S8 세 곳에서 반복 |
| "고령층 피해 게임" | 65세 이상은 읍·면 지역 카드와 S1 1장에만, 지표·색·미션에 쓰지 않음 |
| "이동진료로 해결" | MVP에 그 장치가 없다. S8에 "모델이 다루지 않는 것"으로만 |

### 8-5. 실제 자료와 게임 가정의 경계 (요약)

- **실제 자료여야 하는 것**: 읍·면·리 이름과 경계, 리 인구, 읍·면 65세 이상, 지소 위치·이름, 현재 진료일정, 도로망, 지형.
- **계산값**: 접근시간 행렬, KPI, 배분 지형도, 목표치, 참고 배분, 리 대표점.
- **게임 가정으로 허용**: 진료일 단위와 동질성, 5일 상한, 10·15·20 기준과 균등 이용, 추가 진료자원 +5일(미션 총량 15), 정수 배분.
- **금지**: 검증되지 않은 효과(이동진료·원격협진·고령 가중 결과)를 값으로 만드는 것.

### 8-6. 65세 이상 정보의 취급

읍·면 단위 비율은 실제 자료이므로 S1 1장과 지역 카드에 표시한다. 법정리 단위는 추정이라 **표시하지 않는다.** 어떤 지표·색·크기·미션에도 65세 이상을 쓰지 않는다. 실험에서 고령 가중이 별도의 강한 전략을 만들지 않았고, 리 단위 자료가 추정이기 때문이다.

### 9-2. 캡스톤 데모에서 반드시 보여야 할 장면

7. (선택) 실험실 B=20: 한 배분이 거의 모든 지표에서 앞서며 갈등이 사라진다.

## 10. Opus 5.5 implementation handoff

### 10-1. 확정된 제품 불변식

1. 자원은 **진료일(주당, 정수 0~5, 지소당)** 이며 금액이 아니다.
2. 접근성은 **OSRM car 도로망 시간**, 혼잡·대기 없음. 걸어봄 foot 모델을 쓰지 않는다.
3. **A_i = min(5, Σ_{t_ij ≤ T} x_j)**, S_m·KPI 1~6·Δ 정의는 4-5·4-6절 그대로. 바꾸면 제품 의미 변경이다.
4. **총점·등급·별점 없음.** 6개 지표는 항상 함께 보인다.
5. **원·버퍼·등시선 면을 서비스권으로 그리지 않는다.** 도달은 마을 상태로 표현하고, 개별 관계(어느 지소가 어느 마을에 닿는가)는 hover·선택·포커스·변화 시점에 시간값과 함께 읽을 수 있게 한다. 표현 기법은 구현자 결정이며 161개 선을 항상 동시에 그리라는 요구가 아니다(6-6절).
6. 색만으로 상태·증감·판정을 구분하지 않는다.
7. 금지어(5-12절)를 화면·툴팁·라이브 영역·URL 문구 어디에도 쓰지 않는다.
8. 참고 배분은 플레이어가 미션을 확정하기 전에 보이지 않는다.
9. 세 기준일·출처·routing profile·실제/계산/가정 분류는 manifest 한 곳에서 온다(10-2-2). 하드코딩 금지.
10. 런타임에 외부 서비스 호출이 없다(OSRM·지도 타일·분석 API 없음). 정적 배포로 동작한다.
11. 세션은 브라우저 안에서만 산다. 서버 저장·계정·개인정보 수집 없음.
12. 65세 이상은 읍·면 맥락 정보로만. 리 단위 추정치는 화면에 없다.
13. 걸어봄 제품(`api/`·`web/` 런타임·운영 배포 경로)을 바꾸거나 깨뜨리지 않는다. 같은 저장소를 쓰더라도 새 제품은 **별도 패키지·별도 빌드·별도 CI job**이며 기존 job의 결과에 영향을 주지 않는다.
14. 미션 자원은 **실제 10일(REAL DATA) + 추가 5일(SIMULATION ASSUMPTION) = 15일(가상 정책실험)** 이다. 15가 나오는 모든 화면에서 이 분해와 두 배지가 함께 보이고, 기준선 `현재 실제`는 10일이며, 디브리핑은 차이에 추가 5일의 효과가 섞여 있음을 밝힌다(4-4절). 권고형 문장은 금지어다.
15. 앱 데이터는 최신 저장소와 원자료에서 **재현 가능한 생성 단계**로 만들어지고 10-2-2의 provenance를 함께 가진다. 임시 디렉터리의 실험 산출물은 영구 의존성이 아니다(10-2-1).

### 10-2. 데이터 산출물과 인계 규약

#### 10-2-1. 인계 규약

- **기존 실험 산출물은 참고·대조용이다.** 2026-09 반증 실험의 산출물(`matrix.json` 등)은 개발 PC의 Windows Temp/scratchpad 아래 `…\Temp\claude\c--Users-sdsdo-Documents-geoleobom\7c930891-d083-46fc-9221-faa076e9b1ee\scratchpad\exp2\`에 있다. **이 경로를 제품·빌드·테스트의 영구 의존성으로 만들지 않는다.** 임시 디렉터리는 언제든 사라진다.
- **구현자는 재현 가능한 정적 앱 데이터 생성 단계를 만든다.** 최신 저장소와 원자료(공주시 인구 자료, 보건소 공개 일정·지소 목록, OSM 추출본, DEM)에서 시작해 10-2-3의 산출물을 만드는 스크립트·절차를 두고, 다시 실행한 결과가 저장소에 들어간 정적 데이터와 같아야 한다.
- **실험 산출물과의 대조는 한 번 한다.** 재생성한 161×10 행렬, 현재 실제 배분의 KPI, B=15 우열 없는 배분 수를 실험 산출물과 비교해 일치 여부와 차이의 원인(OSM 판본·프로필·수요점 좌표 차이 등)을 manifest 또는 생성 보고에 기록한다. 대조가 끝난 뒤에는 실험 산출물이 없어도 모든 것이 다시 만들어져야 한다.
- 실험 산출물 중 저장소에 남길 가치가 있는 것(수요점 좌표·지소 좌표·행렬)은 **원자료로 재생성되는 형태**로 옮긴다. 파일을 그대로 복사해 "출처: scratchpad"로 남기지 않는다.
- 파일명·디렉터리·스크립트 구조는 구현자가 최신 저장소를 보고 정한다. 이 문서는 정하지 않는다.

앱이 읽는 데이터에는 최소 아래 항목이 **데이터와 함께**(별도 문서가 아니라 manifest로) 있어야 한다. 화면의 모든 기준일·출처·분류 문구는 여기서 읽는다(8-3절).

| 항목 | 내용 |
|---|---|

| 보건지소·진료일정 기준일·출처 | 지소 10곳 목록의 출처, 의과 순회진료 일정 기준일(2026-04-13), 격주→평균 환산 규칙 |

| routing profile | OSRM 버전·이미지 digest, **car** 프로필과 그 판본, 호출 조건(혼잡·대기 없음) |
| 수요점 161개의 의미 | 법정리 1곳 = 대표점 1개, 대표점을 정한 방법, 리 주민 전체가 그 점에 있다는 단순화 |

| 분류 | 각 항목에 REAL DATA / DERIVED / SIMULATION ASSUMPTION 표기. 현재 10일은 REAL DATA, 추가 5일 진료자원은 SIMULATION ASSUMPTION |

- **성능**: 6-12 5항을 전시 기기 또는 통합 GPU 노트북에서 실측.
- **실제 흐름 1회**: 데스크톱 1440 브라우저로 S0→S6까지 도움 없이 10분 이내. 768 시트 모드 1회.
