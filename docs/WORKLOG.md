## 열린 문제

조작 편의(설계안 6-22)에서 사람이 볼 것:
- 조작법 판의 문구와 자리(왼쪽 아래, 읽는 법 위 `[조작법]`)가 처음 보는 사람에게 찾기 쉬운지. 판은 열려 있는 동안 왼쪽 아래 말풍선 몇 개를 가린다(읽는 법과 같음).

지도 W A S D 이동(설계안 6-21)에서 사람이 볼 것:
- 빠르기(1초에 화면 높이 약 0.9개)와 출발·멈춤(0.2초 · 0.4초)이 손에 맞는지. 숫자는 `app/src/stage/keyPan.ts` 맨 위 세 값이다.
- 화면 낭독기의 탐색 모드는 글자 키를 먼저 가져가므로, 낭독기 사용자에게 W A S D는 닿지 않을 수 있다(말풍선 키 조작은 그대로).

S5·S6 전달력(설계안 6-20)에서 사람이 볼 것:
- 처음 보는 사람이 S5에서 판정 → 얻은 것·잃은 것 순으로 읽는지, S6에서 갈래 줄을 눌러 지도와 잇는지. 테스트 통과는 이해도를 말하지 않는다.

S6 겹쳐 보기·마우스(설계안 6-19)에서 사람이 볼 것:
- 겹쳐 보기의 갈래 표현(세 칸 판·울타리·받침)이 학생에게 읽히는지, 「배분에 따라 갈림」을 닿음 여부로 나눈 정의가 의도와 맞는지(설계안 6-19 「해석 차이」).
- 1100×800 부근에서 S6 섬이 아주 작다(변경 전과 같음). 판·말풍선을 피하느라 생기는 기존 한계다.

추후 평가·개선 후보(오류가 아니다. 확인해서 문제가 없으면 고치지 않는다):

- 나무·집 모형의 분위기와 시각적 완성도 평가(아기자기한 디오라마 느낌).
- S6에서 고른 갈래의 청록 집(지붕·벽 + 집 둘레 빛)이 전체 조망에서도 충분히 잘 보이는지. 받침이 없어진 뒤 「모두 닿지 않음」과 「지소 없음」을 판의 갈래 줄로 가르는 것이 충분한지도 함께.

디오라마 P1·P2(설계안 6-18)에서 사람이 볼 것(P2 마을 받침은 6-25에서 없앴다):

- 저사양 노트북(5500U)에서 적응 화질이 내려가 조작이 끊기지 않는지는 아직 재지 않았다(발표 녹화는 기준 기기 데스크톱으로 한다). `PERF_PROFILES=gpu PERF_HEADED=1 node scripts/perf-probe.mjs`로 한 번 잰다.
- 「주 1~2일」 문구는 1 ≤ A < 3(1.5·2.5일 포함)을 뜻한다. 문구를 「주 1일 이상 3일 미만」처럼 바꿀지는 용어 정리 때 함께 정한다.

노트북에서 땅이 검게 보이던 문제(2026-10-14 팀원 보고, i5-10210U · Intel UHD 추정 · RAM 8GB) — **해결 확인, 배포함**:
- 땅 그림 텍스처(2560×3147, sRGB)의 밉맵 1단계 이상을 검게 두면 보고된 화면과 같은 모양이 재현된다. 땅 그림만 검고, 나무·집·새긴 지명·받침은 그대로다. 새긴 지명(768×240)의 밉맵은 그 기기에서도 정상이었다.
- 그래서 이 텍스처만 밉맵을 직접 만들어 올렸다. 이 PC(D3D11·OpenGL·Vulkan·SwiftShader)에서는 화면과 시작 시간이 그대로다.

- 다른 Intel 기기에서 다시 보이면 받을 정보: 브라우저와 버전, `chrome://gpu`(또는 `edge://gpu`)의 GL_RENDERER·ANGLE 백엔드·드라이버 버전, 확대하면 검은 곳이 줄어드는지.
- "5일 전부터"는 테스트 사이트가 처음 열린 날(10-09)과 맞는다. 지형 코드는 9-25 이후 바뀌지 않았다. 코드 변경으로 생긴 회귀는 아닐 가능성이 크다(추정).
