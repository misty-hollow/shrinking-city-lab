승인된 결정과 그 이유를 적는다. Claude가 정한 기술 결정 중에서는 나중에 다시 참조할 것만 남긴다. 승인되지 않은 제안이나 검토 중인 안은 넣지 않는다.
지금 효력이 있는 개발 방식은 `CLAUDE.md`가 정한다. 아래에서 「대체」 표시가 붙은 항목은 과거 기록이다.

## 제품 결정

### 제품 결정의 원본

제품·화면 결정은 아래 문서에 판 번호와 함께 이미 기록되어 있다. 같은 내용을 두 곳에 두지 않으려고 이 파일에는 옮겨 적지 않는다.

| 범위 | 원본 |
|---|---|
| 제품 정의·계산·데이터·미션·화면 흐름 | `docs/설계안_v0.1.md` (1-1 판정, 6-14~6-17 시각·배치 개정 포함) |
| 화면 UI 표현 | `docs/UI_DESIGN_SYSTEM.md` |
| 공개 범위·남겨 둔 알려진 문제 | `docs/release/RELEASE_READINESS.md` 1·8절 |
| 데이터 이용조건 표기 | `DATA_LICENSE.md` |

위 문서를 바꾸는 결정이 새로 승인되면 그 문서를 고친다. 이 파일에는 날짜, 무엇을, 어디를 고쳤는지 한 줄만 남긴다.

#### D-005 CI 트리거 = PR + main push — 2026-10-12 · 승인: 사용자 요청 · D-006 뒤에도 유지

- **결정**: CI는 `pull_request`(base main), main `push`, 수동 `workflow_dispatch`에서만 돈다. 작업 브랜치 push 트리거(D-002)는 없앤다.
  세 job과 검사 내용·이름(`repository`·`pipeline`·`app`, 필수 체크)은 그대로이고, 경로 필터는 없다.
- **이유**: 병합 조건이 「PR 최신 head의 필수 체크」다. PR이 열린 브랜치에 push하면 PR 실행 하나만 돌아서, 같은 커밋을 두 번 돌리지 않는다.
  (처음 근거는 v1.2 CHANGELOG의 "효율"이었고, D-006 뒤에도 같은 이유로 유지한다.)
- **영향**: PR을 열기 전의 작업 브랜치 push에서는 CI가 돌지 않는다. 그 사이의 확인은 로컬 검증이 맡는다.

#### D-004 병합 방식 = merge commit — 2026-10-12 · 승인: 사용자 요청 · D-006 뒤에도 유지

- **결정**: `gh pr merge <N> --merge --match-head-commit <sha>`. v1.0 때의 「squash — 잠정」(PR #3~#13)을 대체한다.
- **이유**: 사용자가 v1.2에 맞추라고 지시했다. D-006 뒤에도 유지하는 이유는, merge commit이면 검증한 head 커밋이 main 이력에 그대로 남기 때문이다.
  그래서 병합 뒤 「main 트리 = 검증한 head 트리」를 바로 대조할 수 있다.
- **서버**: 룰셋 "Protect main"의 허용 병합 방식은 merge·squash·rebase다(2026-10-14 조회). merge만 남길지는 사용자 설정 사항이다.

## 기술 결정 (Claude가 정한 것)

#### T-004 로컬 검증은 변경 영향에 맞춘다 — 2026-10-14 · T-003 대체

- **결정**: CI의 세 job은 모든 PR에서 전부 돈다(필수 체크). 로컬에서는 이렇게 한다.
  - 코드·데이터·의존성·빌드 설정을 바꾸면: CLI 검사 전부
  - 화면에 영향이 있으면: CLI 검사 + 브라우저 QA + 스크린샷 검토
  - 문서만 바꾸면: 위생 검사와 참조 확인
- **이유**: 사용자 지시(2026-10-14) 「변경 영향에 맞는 검증」을 따랐다. 서버 게이트(필수 체크 세 개)는 그대로라서 병합 기준은 약해지지 않는다.

#### T-002 Codex 리뷰에 목표·기준을 넘기는 방법 — 2026-10-12 · D-006 뒤로는 필수 아님(쓸 때 참고)

- `/codex:adversarial-review --wait --base main --cwd <worktree> <요약>`만 명령 뒤의 문장을 프롬프트에 넣는다.
- 플러그인 1.0.6 소스에서 확인한 사실:
  - 리뷰 입력은 `git log --oneline`(커밋 제목만)과 diff이고, 커밋 본문은 넘어가지 않는다.
  - `/codex:review`는 focus 문장을 받지 않는다.
  - 세션 작업 폴더가 리뷰 대상 worktree가 아니면 `--cwd`가 필요하다.
  - 두 명령 모두 사용자가 입력하는 명령이다.
