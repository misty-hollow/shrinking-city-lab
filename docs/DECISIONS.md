#### D-005 CI 트리거 = PR + main push — 2026-10-12 · 승인: 사용자 요청 · D-006 뒤에도 유지

- **결정**: CI는 `pull_request`(base main), main `push`, 수동 `workflow_dispatch`에서만 돈다. 작업 브랜치 push 트리거(D-002)는 없앤다.
  세 job과 검사 내용·이름(`repository`·`pipeline`·`app`, 필수 체크)은 그대로이고, 경로 필터는 없다.
- **이유**: 병합 조건이 「PR 최신 head의 필수 체크」다. PR이 열린 브랜치에 push하면 PR 실행 하나만 돌아서, 같은 커밋을 두 번 돌리지 않는다.
  (처음 근거는 v1.2 CHANGELOG의 "효율"이었고, D-006 뒤에도 같은 이유로 유지한다.)
- **영향**: PR을 열기 전의 작업 브랜치 push에서는 CI가 돌지 않는다. 그 사이의 확인은 로컬 검증이 맡는다.

#### D-004 병합 방식 = merge commit — 2026-10-12 · 승인: 사용자 요청 · D-006 뒤에도 유지

- **결정**: `gh pr merge <N> --merge --match-head-commit <sha>`. v1.0 때의 「squash — 잠정」(PR #3~#13)을 대체한다.
- **이유**: 사용자가 v1.2에 맞추라고 지시했다. D-006 뒤에도 유지하는 이유는, merge commit이면 검증한 head 커밋이 main 이력에 그대로 남기 때문이다.
  그래서 병합 뒤 「main 트리 = 검증한 head 트리」를 바로 대조할 수 있다.
- **서버**: 룰셋 "Protect main"의 허용 병합 방식은 merge·squash·rebase다(2026-10-14 조회). merge만 남길지는 사용자 설정 사항이다.

## 기술 결정 (Claude가 정한 것)

#### T-007 S6 보기를 바꿔도 카메라를 다시 맞추지 않게 판 자리를 고정한다 — 2026-10-15

- **결정**: S6의 왼쪽 판(폭 480·446px, 높이 고정)과 머리(증감 기준 줄은 겹쳐 보기에서 자리만)를 보기와 상관없이 같은 크기로 둔다. 빈 아래쪽은 지도 조작을 막지 않게 판 자체는 눌림을 받지 않는다.
- **이유**: 무대는 HUD 판이 바뀌면 섬을 다시 맞춘다. 판 크기가 보기마다 달라 겹쳐 보기 ↔ 미션 보기 전환마다 섬이 움직이고(거리 85 ↔ 97), 카메라 맞추기에 CPU 4배 느림 기준 약 200 ms가 걸렸다. 고정 뒤 전환은 이 PC에서 7~15 ms, CPU 4배 느림에서 26~67 ms이고 섬은 그대로다(1024·1100·1280·1366·1440·1920 측정).
- **거부한 대안**: 보기를 바꿀 때 카메라를 잠그는 무대 쪽 예외. 판이 섬을 덮을 수 있다.

#### T-006 정지 화면에서도 화질을 되돌린다 — 2026-10-15

- **결정**: 내려간 단계에서 화면이 5초 넘게 멈춰 있으면 한 묶음(약 90프레임 또는 3초)만 같은 화면을 다시 그려 판단한다. 넉넉하지 않으면 간격을 두 배씩(최대 60초) 늘린다. 판단 규칙은 그대로다(`stage/quality.ts`).
- **이유**: 무대는 멈춰 있으면 그리지 않는다. 그래서 일시적 멈춤으로 내려간 단계가 플레이 화면에서는 근거 없이 그대로 남았다. 측정: 변경 전에는 0.75배 해상도로 남았고, 변경 후에는 16초 안에 최고 단계로 돌아왔다(DPR 1, CPU 20배 느림으로 일부러 낮춘 뒤).
- **거부한 대안**: GPU 이름으로 고성능 기기를 골라 단계를 고정하는 방법. 이름은 성능을 말하지 않고, 실제 프레임을 근거로 하라는 사용자 지시와도 맞지 않는다.
- **나무 줄이기**: 인스턴스 순서를 씨앗 고정으로 섞어, 앞에서 절반을 남겨도 고르게 줄게 했다(`trees.ts` `scatterOrder`).

#### T-005 마을 받침은 지형 재질이 칠하고, 적응 화질은 되돌림만 더한다 — 2026-10-15

- **받침**: 마을별 받침 모양(부호 거리 + 마을 번호)을 땅 그림 좌표의 작은 텍스처(25 m 칸, 밉맵 없음)로 한 번 굽고, 지형 `MeshBasicMaterial`에 조각을 끼워 칠한다. 마을 상태는 256×1 텍스처로 올린다.
  - 드로우가 늘지 않고 지형에 꼭 붙는다(떠 있거나 묻히지 않는다). 굽기는 이 PC에서 약 75 ms다.
  - 거부한 대안: 원판 인스턴스 한 층(드로우 +1, 경사에서 떠오르거나 묻힘), 집마다 원(가까이서 기계적인 표지처럼 보였다 — 시험 화면), 굽은 땅 그림에 그려 넣기(단계가 바뀔 때마다 큰 텍스처를 다시 올려야 한다).
- **적응 화질**: 기존 판단(26 ms 넘으면 한 칸 내림)은 그대로 두고 되돌림과 잠금만 더했다(`stage/quality.ts`). 새 단계나 설정 화면은 만들지 않았다.
  - 이유: 고성능 데스크톱에서 일시적 멈춤 한 번으로 그 판 내내 0.75배 해상도가 되는 문제를 측정으로 확인했다(설계안 6-18).
  - 초과 샘플링(원래 해상도보다 높게)은 시험에서 차이를 확인하지 못해 넣지 않았다. 다시 볼 때는 같은 카메라로 비교한다.

#### T-004 로컬 검증은 변경 영향에 맞춘다 — 2026-10-14 · T-003 대체
