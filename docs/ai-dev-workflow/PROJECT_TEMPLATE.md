## C. 고위험 기준 (독립 리뷰 대상)

위험도는 파일 위치가 아니라 변경의 실제 영향으로 판단한다. 공통 기준에 프로젝트별 목록을 더하고, 하나라도 고위험이면 고위험.

| 변경 | 위험도 |
|---|---|
| 새 테스트 추가, 검증 강화 | 저위험 |
| 기존 테스트의 기준 약화·삭제·건너뛰기 | 고위험 |
| 새 CI 검사 추가 | 저위험 |
| 기존 CI 검사 제거·우회·조건 완화 | 고위험 |
| 빌드 문구·주석·로그 메시지 수정 | 저위험 |
| 빌드 결과물, 배포 대상, 패키징 동작, 의존성 추가·교체 (테스트 하네스·브라우저 실행기 포함) | 고위험 |
| 보안·권한·결제·데이터 무결성·외부 전송 | 고위험 |
| 의도한 화면 변경에 따른 기준 스크린샷 갱신 (전후 경로·사유를 REPORT에 적고 해당 화면을 ③ 항목에 포함) | 저위험 |
| 의도하지 않은 화면의 기준 갱신, 비교 허용 오차·마스크 확대 | 고위험 |
| 운영 규칙·CLAUDE.md·공통 규칙 사본 변경 중 검증·승인·권한 기준이 바뀌는 것 | 고위험 |
| 메인이 영향 범위를 확신하지 못하는 변경 | 고위험 |

프로젝트별 고위험 파일 (어떤 수정이든 고위험):

## H. 데이터 분리와 커밋 제외

실행 검증은 격리된 컨텍스트에서만 돈다:
- 브라우저: 매 실행 새 브라우저 컨텍스트 생성(이 조건에서 localStorage·IndexedDB가 실제 프로필과 분리됨)
- 데스크톱: userData를 임시 디렉터리로 지정. 브라우저 격리가 데스크톱 저장 데이터를 보호하지는 않음
- 실제 세이브·에셋 경로를 쓰지 않는다. 쓸 수밖에 없으면 작업 전 복사와 복구 방법을 여기 적는다

절대 커밋하지 않는다: `.claude/settings.local.json`과 백업, 인증 정보, 로컬 환경 파일, (프로젝트별 추가). `.claude/agents/` 정의 파일은 개별 지정해 커밋한다. `git add .claude/`는 쓰지 않는다.
