# 플레이테스트 체크리스트 · 관찰 항목

이 문서는 사람 플레이테스트를 진행하는 팀원을 위한 것입니다.
목적은 두 가지를 확인하는 것입니다.

1. 참가자가 설계안의 **학습 목표 3개(2-5절)**를 스스로 알아차리는가
2. **오해 방지 표(8-4절)**의 오해가 실제로 생기지 않는가

"재미있었나"보다 **무엇을 이해했고 무엇을 잘못 읽었는가**를 기록합니다.

- 권장 인원: 5~8명(서로 다른 전공·나이대)
- 한 사람당 15~20분
- 관찰자 1명 + 진행자 1명

## 1. 준비

- [ ] 전시와 같은 기기·해상도(1920×1080 권장)·브라우저(Chromium 계열)를 씁니다. 가능하면 전시 스피커도 씁니다.
- [ ] 운영 빌드를 씁니다(`npm run build` → `npx vite preview`, 또는 실제 배포 주소).
- [ ] 전시 모드(`?kiosk=0` 없이)로 엽니다. 90초 무입력 복귀도 관찰 대상입니다.
- [ ] 소리는 켠 상태로 시작합니다. 참가자가 끄는지도 기록합니다.
- [ ] 화면 녹화는 참가자 동의를 받은 경우에만 합니다. 기록지에는 **이름·연락처를 적지 않습니다**(참가자 번호·나이대·전공 정도만).
- [ ] 진행자 대본은 "이 화면을 자유롭게 해 보시고, 생각나는 것을 소리 내어 말해 주세요"까지만 씁니다. 조작 방법·정답을 알려 주지 않습니다.
- [ ] 막혀서 도움을 준 경우 **무엇을, 언제** 알려 줬는지 기록합니다.

## 2. 화면별 관찰 항목

| 화면 | 볼 것 | 기록 |
|---|---|---|
| S0 시작 | 시작 버튼을 찾기까지 걸린 시간. 한계 한 줄("정책을 추천하지 않아요")을 읽는가 | 초 / 예·아니오 |
| S1 소개 3장 | 읽는가, 바로 넘기는가. "진료일"의 뜻을 말로 설명할 수 있는가 | 장별 머문 시간 |
| S2 튜토리얼 | 기준(10·15·20분)을 바꾸라는 요구를 알아차리는가. **불 꺼진 마을**을 어떻게 읽는가("사람이 없다"로 오해하지 않는가) | 발화 그대로 |
| S3 브리핑 | 15일이 `실제 10일 + 가정 5일`임을 알아차리는가 | 발화 그대로 |
| S4 플레이 | 말풍선을 눌러 하루를 놓는 조작을 스스로 발견하는 데 걸린 시간. − 손잡이(빼기)를 발견하는가. 놓기 전 미리보기(숫자·집 테두리)를 활용하는가. 되돌리기와 위에서 보기를 쓰는가 | 첫 조작까지 초, 막힌 지점 |
| S4 지표 | 6개 지표 중 어느 것을 보는가. 미션 목표선을 이해하는가 | 손가락·시선이 가는 곳 |
| S5 결산 | 얻은 마을과 잃은 마을을 **둘 다** 말하는가 | 발화 그대로 |
| 미션 2·3 | 목표가 바뀌면 배분이 달라져야 함을 알아차리는가 | 배분을 바꾼 방식 |
| S6 세 개의 공주 | 세 배분이 서로 다른 지도라는 점을 말하는가 | 발화 그대로 |
| S8 자료와 한계 | 스스로 여는가. 진료일정 기준일과 "방문 전 확인" 안내를 보는가 | 예·아니오 |
| 전체 | 오류·멈춤·버벅임. 소리를 끄는가. 90초 복귀를 겪었는가 | 시각·상황 |

## 3. 끝난 뒤 질문 (5분)

열린 질문으로 먼저 묻습니다. 참가자가 답한 뒤에만 보기를 보여 줍니다.

**학습 목표 (2-5절)**
1. "평균을 올리는 배분과 빈 곳을 없애는 배분이 같았나요, 달랐나요? 어떻게 달랐나요?" → 목표가 다르면 좋은 배분이 다르다
2. "평균이 비슷한 두 배분에서 손해를 본 곳이 같았나요?" → 평균 뒤의 지역별 희생
3. "10분·15분·20분 기준을 바꿨을 때 무엇이 달라졌나요?" → 기준 자체가 선택이다

**오해 확인 (8-4절, 맞다·아니다·모르겠다)**

| # | 문장 | 바른 답 |
|---|---|---|
| a | 이 게임은 공주시가 이렇게 해야 한다고 권한다 | 아니다 |
| b | 15일은 지금 공주시의 실제 진료일이다 | 아니다(실제 10 + 가정 5) |
| c | 진료일을 5일 늘려야 한다는 뜻이다 | 아니다 |
| d | 15분이 정해진 표준 기준이다 | 아니다 |
| e | "도로망 12분"은 실제로 주민이 걸리는 시간이다 | 아니다(혼잡·대기 없는 도로망 접근시간) |
| f | 진료일 하루 = 의료서비스 전체 | 아니다 |
| g | 길을 따라 흐르는 빛은 실제 의료진·차량의 이동이다 | 아니다(접근성 변화의 표현) |
| h | 집 한 채는 실제 건물 한 채다 | 아니다(주민 약 50명 기호) |
| i | 참고 배분이 정답(최적)이다 | 아니다 |
| j | 보건지소는 지금도 화면의 일정대로 운영된다 | 아니다(2026-04-13 기준, 방문 전 확인) |

마지막으로 "가장 헷갈렸던 순간은 언제였나요?"를 묻습니다.

## 5. 판단 기준 (릴리스 판단용 권장값)

| 항목 | 통과 기준 |
|---|---|
| 첫 조작 | 도움 없이 60초 안에 첫 진료일을 놓은 사람이 참가자의 80% 이상 |
| 학습 목표 | 목표마다 참가자 절반 이상이 ○ |
| 오해 | a·b·c·e·i·j는 틀린 사람 0~1명. 2명 이상이면 해당 문구·배치를 고칩니다(계산·미션은 바꾸지 않음) |
| 오류 | 콘솔 오류·멈춤 0 |
| 막힘 | 같은 곳에서 3명 이상 막히면 그 화면의 안내 문구를 검토합니다 |

결과 요약과 고칠 점은 `docs/release/` 아래 날짜별 파일(예: `playtest-2026-10-xx.md`)로 남깁니다. 개인정보는 넣지 않습니다.
